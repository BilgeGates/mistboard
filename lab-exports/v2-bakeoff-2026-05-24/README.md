## Filename convention

`game-NNNN-{outcome}-tier1-{subject_color}.jsonl`
- `NNNN` — game index 0000-0031 (g0012 is missing — see "Notes" below)
- `outcome` — W / L / D, **v2-centric** (W = v2 won, L = v0.9.5 won, D = draw)
- `subject_color` — the color v2 played (alternates white/black by game parity)

## Event format

Each game file is JSONL with one event per line. Event types:

- `room-created` — first line, identifies room + variant (`"dark-chess"`)
- `move-played` — every move in the game, with `from`/`to`/`promotion`, `color`, `compute_ms`/`thinkTimeMs`

Same format the `apps/web` bakeoff viewer reads (see `apps/web/src/replay.ts`'s
event-replay path + `apps/web/src/bakeoff.ts`).

## Manifest schema

`manifest.json` follows the existing `bakeoff-belief-smoke/manifest.json` convention. Key fields:

- `tier1_version`: `"engine-v2 (rust-port 551cbaf)"` — the v2 engine variant under test
- `opponent`: `"v0.9.5-equivalent"` — Tier-1 baseline (configs/tier1-v1.json)
- `tier1_record`: `{wins: 28, losses: 0, draws: 3}` — **v2-centric**
- `games[]`: per-game metadata pointing at `games/<filename>` paths
  - `index`, `tier1_color` (= v2's color), `outcome` (W/L/D), `plies`, `end_reason`

## Notes for downstream use

- **g0012 is missing** — that game crashed (P-soundness violation: 1M cap dropped the truth in this seed; subsequent observation had zero consistent prev). The shard isolation contained it; ladder continued. Document somewhere that this is a 3.1% crash rate at p_max=1M, expected.
- **3 draws are endgame conversion failures.** All 3 have v2 with crushing material vs lone-king-plus-shreds (g0023: 17 vs 3 material; g0024: 15 vs 0; g0029: 13 vs 0). v2 cycles in 3-fold repetition. Root cause: Stockfish-leaf at depth-1 sees +material score regardless of mate progress, so CFR has no gradient toward king-hunt. This is a known structural blind spot (catalogued in `docs-private/engine-track/` and `~/.claude/projects/-Users-brianliou-projects-mistboard/memory/engine_obscuro_blind_spots.md`).
- For homepage showcase: probably prefer the cleaner wins (king-capture in <80 plies). Suggestions: g0004 (33 plies, fastest), g0005 (54 plies), g0008 (61 plies). Avoid the 3 draws unless you want to be honest about engine weaknesses.

## Viewer

Drop manifest + games into `apps/web/public/<some-tag>/` and open:
```
http://localhost:3000/?bakeoff=/<some-tag>/manifest.json
```
(Wildcard `apps/web/public/bakeoff-*` is gitignored, so a manual placement works locally without polluting git.)

The viewer uses `apps/web/src/bakeoff.ts` + `apps/web/src/replay.ts`. Three-pane layout: truth board on top, white POV + black POV side-by-side below. Click games in the right rail to load them.
