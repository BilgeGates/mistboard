Fortress Xiangqi · rules experiment

Do "veteran" soldiers make the game more stable?

A soldier in Fortress Xiangqi attacks in three directions once it crosses the river, but only pushes straight forward on its own half, so it makes a fine attacker and a poor defender. This experiment removes that gate: soldiers move forward and sideways from move one (never backward), and we measure what happens across hundreds of self-play games per rule at equal engine strength.

How this was measured
  • Two rules, one code path. Both run the shipped Fairy-Stockfish variant; the only difference is the soldier. BASE uses soldier = p + soldierPromotionRank = 5 (sideways only after the river). VET replaces it with customPiece = p:fsW, a forward-and-sideways wazir, no promotion. Validated by move-set diff: identical to BASE except home-half soldiers gain their lateral step.
  • Equal strength, not equal compute. Every move is a fixed-depth search (depth 12). VET's larger branching would be handicapped by a fixed node budget; at fixed depth both rules search to the same horizon with near-equal node counts (BASE ~51k, VET ~56k).
  • Balanced openings. Each game starts from 6 random legal plies (deterministic per seed); openings already past ±250cp are discarded so no game begins pre-decided. 200 kept games per rule.
  • Metrics. Eval volatility = mean absolute per-ply change in the engine's red-POV score. Comeback = a decisive game whose winner was once behind ≥200cp. Everything else is read straight from the move list via a board replayer; no game kernel involved, so the two rules stay symmetric.
  • Caveats. Self-play at depth 12, not human play. Repetitions are scored as draws (the perpetual-chase upgrade is server-side and not modeled here). Absolute cp is only compared within a game, never across rules.
